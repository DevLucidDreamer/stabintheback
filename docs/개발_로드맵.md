## 0. 한 줄 요약

마인크래프트 **마검탈출맵** 리메이크 = 일상 사물(국자·냉동참치)을 무기로 쓰는 **1인칭 병맛 멀티플레이 파티게임**. 첫 테마는 **"캠핑 가기 전 집에서 준비물 챙겨 나가기"**. 싱글플레이 기반(이동/상호작용/무기/체크리스트/집 맵)은 완성됐고, 현재 **멀티플레이(Mirror) Phase 1** 진행 중이다.

## 2. 현재까지 구현 요약

### 2.1 싱글플레이 시스템 (`Assets/Scripts/`) — ✅ 동작
| 스크립트 | 역할 |
|---|---|
| `PlayerController.cs` | 1인칭 이동(WASD)·마우스 룩(몸 yaw / 카메라 pitch)·달리기(Shift)·점프(Space)·중력·물체 밀기. **멀티용 훅 추가됨**: `SetInputEnabled`, `Pitch`, `CameraTransform`, `SetRemotePitch` |
| `Interactable.cs` | 상호작용 오브젝트 추상 베이스(`displayName`/`GetPrompt`/`Interact`) |

| `Weapon.cs` | 줍는 무기(들었을 때 포즈), `Interact`→`PickUp` |
| `PlayerInteraction.cs` | 화면 중앙 레이캐스트(3m), 좌클릭 상호작용/스윙, 우클릭 들고도 열기, G 버리기, 스윙 연출(3단계). **멀티용 `SetInputEnabled` 추가됨** |
| `CollectibleItem.cs` | 캠핑 준비물, 챙기면 체크리스트 반영 + 비활성화 |
| `ItemChecklist.cs` | E키로 **왼쪽 아래에서 3D 클립보드**를 들어 목록 확인, 자동 등록/체크. **멀티용 `SetInputEnabled` 추가됨** |
| `Editor/HouseBuilder.cs` | `Tools > House > Build/Clear House`로 집 맵 절차 생성 |

**조작**: WASD 이동 · 마우스 시야 · Shift 달리기 · Space 점프 · 좌클릭 상호작용/스윙 · 우클릭(무기 든 채) 열기 · G 무기 버리기 · E 체크리스트 · Esc 커서 해제

**집 맵**: 내부 32×24m, 천장/바닥/현관 이중문 포함. 거실·주방·침실·서재·욕실·복도. 서랍 6개, 냉장고(문+냉동참치), 무기(국자·냉동참치), 장식 주방도구.

**캠핑 준비물 8종(9개)**: 텐트, 침낭, 손전등(서재 서랍), 라면×2(주방 서랍), 물병(냉장고 안), 코펠, 구급상자, 캠핑의자.

> ⚠️ **무기 공격 판정/데미지는 의도적으로 미구현** — 현재는 스윙 연출만.

## 3. 페이즈 로드맵

> 각 페이즈는 **네트워킹**과 **게임플레이**를 순서대로 쌓는다. 완료 기준(Acceptance)을 만족해야 다음 페이즈로 넘어간다.
> 현재 인터넷 연결은 **Unity Relay**를 사용한다. Steam 출시 준비가 끝나기 전까지 별도 포트 포워딩 없이 테스트할 수 있다.

### Phase 0 — 네트워크 기반 · ✅ 완료
- **목표**: 패키지 설치 + 빈 방 Host/Client 연결 검증.
- **완료 기준**: 두 에디터(원본/ParrelSync 클론)에서 Host·Client로 붙어 콘솔 에러 없이 유지. ✔

### Phase 1 — 플레이어 스폰 & 이동/시선 동기화 · ✅ 완료
- **목표**: 접속당 플레이어 1명 스폰, 로컬만 입력/카메라/오디오, 원격의 위치·yaw·pitch 동기화.
- **완료 기준**: `NetworkPlayer.prefab` + 스폰포인트 + 로컬/원격 분리 + 이동·시선 동기화 검증. ✔

### Phase 2 — 상호작용(Openable) 네트워크 동기화 · 🔷 코드 완료, 에디터 실행 대기
- **목표**: 서랍·문·냉장고 열림 상태를 서버 권한으로 모든 클라이언트에 동기화.
- **구현**: `Openable`은 싱글용 그대로 두고 `IOpenableNetworkController`로 위임 분리. `NetworkOpenable`(SyncVar + `Command(requiresAuthority=false)` + 훅)이 서버 권한 동기화. 늦은 접속자는 `OnStartClient`에서 현재 상태 반영. 상세: [`multiplayer_phase2_setup.md`](multiplayer_phase2_setup.md)
- **남은 작업(에디터 수동)**: `NetworkDemo.unity`에서 `Tools > Multiplayer > Phase 2 > Setup Interactable Sync` 실행 → 씬 저장.
- **완료 기준**: 한 명이 연 서랍/문/냉장고가 **모든 클라이언트에서 동일하게** 열리고 닫힘(늦게 접속한 클라이언트도 현재 상태로 보임).

### Phase 3 — 아이템 / 체크리스트 네트워크 동기화 (협동) · 🔷 코드 완료, 에디터 실행 대기
- **결정됨**: **팀 공용(협동)** — 아무나 챙기면 모두의 진행도에 반영.
- **구현**: 아이템에 고유 ID 부여(NetworkIdentity 미부착 — 서랍/냉장고 자식 중첩 회피). `CampChecklistManager`(NetworkIdentity 1개)가 서버 권한으로 획득/진행 관리, `RpcCollected`로 아이템 숨김+진행 동기화, 늦은 접속자 `CmdRequestSync`로 동기화. `ItemChecklist`는 매니저 있으면 공용 진행도 렌더. 상세: [`multiplayer_phase3_setup.md`](multiplayer_phase3_setup.md)
- **남은 작업(에디터)**: `Tools > Multiplayer > Phase 3 > Setup Checklist Sync` 실행 → 저장.
- **완료 기준**: 아무나(서랍/냉장고 안 포함) 챙기면 **모두의 클립보드**에 반영, 재획득 불가, 늦은 접속자도 현재 상태.

### Phase 4 — 무기 시스템 네트워크화 + 공격 판정 도입 · 🔷 코드 완료, 에디터 실행 대기
- **구현**: 무기에 고유 ID 부여. `WeaponNetworkManager`(NetworkIdentity 1개)가 "누가 어떤 무기 소지"를 서버 권한 관리, `RpcHold/RpcFree/RpcSwing`으로 각 클라가 로컬 무기 복사본을 손에 붙이거나 내려놓고 스윙 재생. 스윙 판정(넉백)은 각 클라 로컬 수행 + `OnSwingHit` 훅. 상세: [`multiplayer_phase4_setup.md`](multiplayer_phase4_setup.md)
- **남은 작업(에디터)**: `Tools > Multiplayer > Phase 4 > Setup Weapon Sync` 실행 → 저장.
- **완료 기준**: 원격 플레이어의 무기 소지/스윙이 보이고, 스윙 시 판정(넉백)이 동작.
- **한계/후속**: 데미지·체력 시스템은 아직 없음(판정 "도입"만). 떠도는 큐브는 미네트워크라 넉백이 클라별 상이 — 네트워크 히트 타깃은 후속.
- **열린 질문**: 코드네임 `stab in the back`가 시사하는 **배신자/PvP 요소** 여부 — 데미지 시스템 설계 시 확정 필요.

### Phase 5 — 마검 전투: 원킬·리스폰·권력 이동 (배신) · 🔷 코드 완료, 에디터 실행 대기
- **컨셉(마검탈출맵)**: 소수의 마검(국자·냉동참치)을 뺏고 빼앗으며 권력을 유지하는 협동+배신. 마검 = 한 방 즉사.
- **구현**: 마검 소지자의 스윙이 앞의 다른 플레이어를 맞히면 서버 권한으로 **즉사**(`WeaponNetworkManager.ServerSwingKill`). 사망 시 **즉시 리스폰**(스폰 지점) + 들고 있던 마검을 죽은 자리에 **떨어뜨려 권력 이동**(`PlayerHealth`). 스폰 직후 짧은 무적. 상세: [`multiplayer_phase5_setup.md`](multiplayer_phase5_setup.md)
- **남은 작업(에디터)**: `Tools > Multiplayer > Phase 5 > Setup Combat` 실행(NetworkPlayer 프리팹에 PlayerHealth 추가).
- **완료 기준**: 마검 소지자가 상대를 스윙으로 처치→상대 즉시 리스폰, 처치당한 사람이 들었던 마검이 바닥에 떨어져 타인이 습득 가능, 스폰킬 방지.

### Phase 6 — 스테이지 전환 + 두 번째 스테이지 · 🔷 코드 완료, 에디터 실행 대기 (part 1)
- **구현**: `EscapeZone`(현관 밖 트리거) — 체크리스트 완료 + 플레이어 진입 시 서버 권한 `ServerChangeScene`으로 다음 스테이지 로드. 미완료면 안내. Mirror NetworkManager는 씬 전환 시 유지되어 플레이어 재스폰. **Stage2(캠핑장)**는 `Stage2Builder`로 환경+스폰+준비물(장작/마시멜로/부탄가스/랜턴/낚싯대)+마검(도끼/바비큐집게)+매니저+탈출존까지 자동 생성. 상세: [`multiplayer_phase6_setup.md`](multiplayer_phase6_setup.md)
- **남은 작업(에디터)**: `Tools > Stage > Build Stage 2 (Campground)` 실행 → NetworkDemo에서 `Phase 6 > Setup Escape (Stage1 -> Stage2)` 실행 → 저장.
- **완료 기준**: 준비물 완료 후 현관 나가면 Stage2로 전환·재스폰, Stage2 완료 후 탈출존에서 루프.
- **후속(part 2)**: 라운드 타이머, 승패·결과 화면, 마검 최종보유 vs 탈출 승리 조건 확정.

### Phase 6.5 — 대기실(로비) · 🔷 코드 완료, 에디터 실행 대기
- **컨셉**: 숲 들판 한복판 나무 식탁 위에 **냉동참치**가 성검처럼 안치된 "참치 제단". 집으면 그게 **마검**이다.
  대기실에서 이미 원킬·리스폰·마검 뺏기가 돌아가서, 출발 전에 게임의 재미를 미리 체험한다.
- **구현**: `LobbyManager`(준비 인원 집계·카운트다운·씬 전환, 서버 권한), `LobbyReadyZone`(출발 발판),
  `LobbyAltar`(마검 뽑힘 연출), `PracticeDummy`(허수아비), `WorldSign`(월드 팻말).
  `Weapon`에 `OnHeldChanged` 이벤트 추가. 씬은 `Editor/LobbyBuilder.cs`가 통째로 생성.
  상세: [`기획서_대기실.md`](기획서_대기실.md)
- **씬 흐름**: MainTitle → **Lobby** → NetworkDemo(집) → Stage2(캠핑장)
- **남은 작업(에디터)**: `Tools > Lobby > Build Lobby` 실행. (Build Settings 순서와 타이틀의 이동 대상 씬까지 함께 정리된다)
- **완료 기준**: 타이틀에서 접속하면 대기실로 들어오고, 참치를 집으면 마검이 되며,
  전원이 출발 발판에 서면 5초 뒤 집으로 전환된다.

### Phase 7 — 인터넷 서비스 · 🔷 Unity Relay/Vivox 코드 완료, 실기기 검증 대기

## 4. 위임 시 참고(코딩 규칙 / 함정)

- **입력은 새 Input System만** 사용(`Keyboard.current`/`Mouse.current` 또는 InputAction). 구 `UnityEngine.Input` 금지.
- **씬을 손으로 편집하지 말 것** — 대량 오브젝트/컴포넌트 배선은 에디터 도구(예: `HouseBuilder`, `NetworkPhaseXSetup`)로 생성. Unity가 열려 있을 때 씬 YAML 직접 수정은 충돌·손상 위험.
- 로컬/원격 분기는 이미 `SetInputEnabled` 패턴으로 갈라져 있음 — 신규 플레이어 기능도 이 게이트를 따를 것.
- Mirror 권한 모델: **서버 권한 기본**, 이동만 클라이언트 권한(NetworkTransform ClientToServer). 상호작용/아이템/전투는 서버 권한 + Command/Rpc로.
- 무기 공격 판정은 **Phase 4 전에는 넣지 않는다**(현재 스윙 연출만 요구됨).
- **머티리얼이 분홍(마젠타)으로 보일 때**: 이 프로젝트는 URP다. 원인은 대개 둘 중 하나.
  1. `Packages/manifest.json`에 `com.unity.render-pipelines.universal`이 빠져 있다
     → 셰이더 GUID가 통째로 해석되지 않아 **전부** 분홍이 된다. 패키지를 다시 넣으면 복구된다.
  2. 머티리얼이 내장 `Standard` 셰이더로 만들어졌다(URP에서 렌더 안 됨)
     → `Tools > Materials > Fix Pink Materials`로 일괄 수리.
  코드에서는 `Shader.Find("Universal Render Pipeline/Lit")`를 직접 쓰지 말고
  **`PipelineShaders.Lit`** 을 쓴다. Shader.Find는 시점에 따라 null을 돌려주고,
  그때 Standard로 폴백하면 조용히 분홍 머티리얼이 만들어진다.
