# 돌 신전 구현·검증 기록

Unity 6000.3.15f1 / Windows x64. 기존 작업 중인 Unity 프로젝트를 닫지 않고 Temp/TempleValidation에 별도 복사본을 만들어 검사했다.

## 확인한 결과

- 대기실 씬 파일 보존. 활성 빌드 목록은 MainTitle, Lobby, Stage1_StoneTemple 세 씬이다.
- 성배병 원본을 변경하지 않고 평가된 메시 4개를 Unity native Mesh/Material/Prefab으로 변환했다. 65,535 정점을 넘는 파트에는 32-bit index를 사용한다.
- 맵의 스크립트·머티리얼 참조, 네 개 스폰, 오디오 임포트 검사 통과.
- 발판 검사: 최신 위치 반영, 다중 점유 중 한 명 이탈, 점프, 사망, 컨트롤러 비활성, 오브젝트 비활성, 연결 종료, 발판 비활성, 회전, 경계 여유, 잘못된 좌표, 중복 발판 점유 배제 통과.
- 석재 검사: 바닥에 놓인 석재만 영구 고정 조건을 충족하며, 들고 있는 석재는 제외한다.

## 실제 네트워크 프로세스 검사

네 개의 독립 Windows 게임 프로세스를 loopback KCP로 연결했다. 테스트 도구는 복사본에만 추가했으며 원본 프로젝트와 최종 테스트 빌드에는 포함하지 않는다.

1. 네 명 접속 후 기존 대기실에서 신전 씬으로 전환.
2. 첫 발판과 고정 레버, 회랑의 양쪽 발판, 석재 운반/배치, 쌍둥이 계단 레버, 마지막 석재/레버 동기화.
3. 네 개의 봉인 발판에 집결 후 성배병 획득. 네 프로세스 모두 완료 상태 관찰.
4. 성배병으로 다른 플레이어 타격. 네 프로세스 모두 명중 RPC를 한 번 관찰.
5. 피격 플레이어의 사망과 마지막 구간 z=137 복귀, 리스폰 보호 확인.

이 검사는 플레이어 위치를 자동으로 이동시켜 네트워크 판정과 진행 상태를 검증한다. 사람이 직접 점프·운반하는 조작성 테스트나 서로 다른 네 PC의 Relay/인터넷 지연 검증을 대신하지 않는다.

## 발견·수정한 원인

기존 NetworkPlayer 프리팹은 CharacterController와 동적 Rigidbody 중력을 동시에 사용했다. 실제 네 프로세스 검사에서 플레이어가 바닥 아래로 내려가 발판을 놓고 반복 사망하는 현상을 재현했다.

Rigidbody를 kinematic, useGravity=false로 바꾸고 PlayerController.Awake에도 같은 보정을 추가했다. 변경 후 동일한 네트워크 진행 검사가 완료되었다. 사망 시의 별도 래그돌에는 영향을 주지 않는다.

## 검증 범위의 한계

복사본의 Unity Services는 직렬화된 Cloud Project ID를 보유하지만 에디터의 Cloud 연결 상태를 인식하지 못해 정식 출시 검사에서 중단되었다. 원본 Cloud 설정 및 출시 검사 규칙은 완화하거나 변경하지 않았다. 실제 Relay 연결과 음성 동작은 원본 프로젝트의 연결 환경에서 별도 확인해야 한다.

로그: Logs/temple-peer0.log ~ temple-peer3.log, Logs/temple-preview-build.log.
발판 검사 재실행: StoneTempleChecks.BuildAndCheckBatch.
로컬 확인용 Development 빌드: StoneTempleChecks.BuildLocalPreviewBatch.
정식 출시 검사 및 빌드: StoneTempleChecks.BuildReleaseBatch.
